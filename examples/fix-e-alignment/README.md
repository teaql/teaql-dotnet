# Generated Q/E, Checker and graph-save regression

Run against the runtime source in this repository:

```sh
node examples/fix-e-alignment/verify-local.cjs
```

The evaluated three-object fixture covers typed loading, expression failures,
Checker diagnostics, optimistic versions, independent mutation ledgers and
partial unchanged ancestors with a complete modified child. The same database
is used for two rounds. Compact logs and SQLite files are retained; disposable
consumer builds are removed.

`PartialRootProbe.cs` additionally loads a complete child owned by one active
root through two unchanged partial ancestors. Saving under another persisted
root must reject twice without SQL, transactions, ID reservations, policy
resolution/review or audit delivery. Intent and sparse projections survive.
Restoring the original context permits the same graph to update only its leaf.
All ten counters are calibrated by successful operations, including rollback.

Managed-root checks are runtime-owned, driven by the generated module's
canonical reference metadata. Loaded ownership is checked even if the field is
absent from the update delta. A missing create reference is filled from the
active context before the customer Checker; explicit conflicts and changed
final Fix output are rejected. Replacing a Checker does not disable admission.
This does not define application-specific tenant or permission policy.

This behavior requires both the repaired runtime and regenerated module
metadata. Reusing an older generated library is not proof of this contract.
Never hand-edit the generated fixture; its manifest binds every generated byte
and the original model. API discovery uses model-aware Assist, not library
source inspection.
