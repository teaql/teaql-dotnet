# Generated Q/E, Checker and graph-save regression

Run against the runtime source in this repository:

```sh
node examples/fix-e-alignment/verify-local.cjs
```

The evaluated three-object fixture covers typed loading, expression failures,
Checker diagnostics, optimistic versions, independent mutation ledgers and
partial unchanged ancestors with a complete modified child. The same database
is used for two rounds. Compact logs and SQLite files are retained; disposable
consumer builds are removed.

`ProjectionViewsProbe.cs` adds three generated-query combinations twice on a
separate unreset store: a later full query cannot widen a sparse view; two full
views retain independent pending mutations and reject a stale second save; and
a sparse root stays sparse when the same ID also appears as a complete nested
relation. E/JSON perform no hidden I/O. Failed saves preserve the original version
and business intent; only the exact managed BusinessClock Fix may remain added.
All generated implementation files remain unchanged and hash-checked.

`UnchangedViewsProbe.cs` exercises restored value/null edits and repeated clean
saves with sparse fixed fields, a loaded sparse relation, query-only null/zero/
empty properties and row-owned alias values. Every no-op preserves JSON, E load
state, optimistic baseline and lineage with zero provider/transaction/policy/
audit/SQL-log effects. Saving one row preserves another row's pending intent;
invalid alias selection leaves the prior view intact. A genuine write control
must return authoritative values, not reinstall stale derived data. Two rounds
share an unreset SQLite store, independently checked by read-only SQL. This
does not claim typed dynamic schemas, persistent dynamic fields or a public
outer-transaction API that this runtime does not expose.

`PartialRootProbe.cs` additionally loads a complete child owned by one active
root through two unchanged partial ancestors. Saving under another persisted
root must reject twice without SQL, transactions, ID reservations, policy
resolution/review or audit delivery. Intent and sparse projections survive.
Restoring the original context permits the same graph to update only its leaf.
All ten counters are calibrated by successful operations, including rollback.

Managed-root checks are runtime-owned, driven by the generated module's
canonical reference metadata. Loaded ownership is checked even if the field is
absent from the update delta. A missing create reference is filled from the
active context before the customer Checker; explicit conflicts and changed
final Fix output are rejected. Replacing a Checker does not disable admission.
This does not define application-specific tenant or permission policy.

This behavior requires both the repaired runtime and regenerated module
metadata. Reusing an older generated library is not proof of this contract.
Never hand-edit the generated fixture; its manifest binds every generated byte
and the original model. API discovery uses model-aware Assist, not library
source inspection.

## Checker boundaries through generated saves

`CheckerBoundaryProbe.cs` extends this same three-entity example with 28 cases
per unreset round: generated Checker installation without schema, a required
relation, a genuinely incomplete modified object with its root ID loaded,
unchanged partial ancestors, post-Fix range rejection/required-value repair,
and real object-local JSON normalization for three naming profiles. Unknown
and equal/unequal alias collisions must fail before mapping, Checker or Save.
Transport/transaction/audit counters are calibrated by exactly-once positive
graph inserts, and retained SQLite reads independently check physical values.

The only reflection seam reads the **runtime's** checker registry to decorate
the real generated Checkers in this verification example. It is not generated
source discovery, a production customization recipe or a replacement Checker.
No generated implementation is read or hand-edited. The normal verifier runs
all prior examples and the new probe twice on retained, unreset stores.
